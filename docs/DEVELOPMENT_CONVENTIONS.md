# Ondrift FE 개발 컨벤션

## 1. 아키텍처

- React 18, TypeScript, Vite를 기본 스택으로 사용한다.
- `src/app`은 라우팅과 앱 셸, `src/features`는 업무 모듈, `src/components`는 공통 UI, `src/lib`는 API와 범용 유틸리티, `src/types`는 공유 타입을 담당한다.
- 서버 데이터는 API 계층을 통해서만 조회한다. 기본 URL은 `http://localhost:8000/api/v1`이며 `VITE_API_BASE_URL`로 재정의할 수 있다.
- 목록 API는 `{ items, total, page, size, pages }` 형식을 사용한다. 페이지는 1부터 시작하며 마지막 페이지와 빈 목록을 정확히 처리한다.
- API 실패 시 데모 데이터로 전환할 수 있지만, 화면에 데모 모드와 원래 오류를 명시해 장애를 숨기지 않는다.

## 2. 컴포넌트

- 컴포넌트와 파일은 PascalCase, 훅은 `use` 접두사, 함수와 변수는 camelCase를 사용한다.
- 한 컴포넌트는 한 가지 책임을 갖는다. 데이터 로딩, 화면 상태, 표현 컴포넌트를 가능한 한 분리한다.
- 공통 상태(로딩, 오류, 빈 결과), 페이지네이션, 배지, 표, 카드 패턴은 재사용 컴포넌트로 구현한다.
- 모든 목록 렌더링은 안정적인 도메인 ID를 `key`로 사용한다.

## 3. 스타일

- 전역 디자인 토큰은 CSS 사용자 정의 속성으로 선언하고 색상, 간격, 반경, 그림자를 재사용한다.
- 모바일 우선 반응형 레이아웃을 적용한다. 좁은 화면에서 내비게이션은 축소되고 표는 가로 스크롤을 허용한다.
- 상태 색상만으로 의미를 전달하지 않으며 텍스트 또는 아이콘 레이블을 함께 제공한다.
- 인라인 스타일은 데이터 기반 시각화처럼 계산이 필요한 값에만 제한한다.

## 4. 접근성

- 시맨틱 HTML, 올바른 제목 계층, `nav`, `main`, `table`, `button`을 사용한다.
- 모든 상호작용 요소는 키보드로 접근 가능해야 하며 명확한 포커스 표시를 제공한다.
- 아이콘 전용 버튼에는 접근 가능한 이름을 제공한다.
- 차트에는 텍스트 요약 또는 데이터 레이블을 제공하고, 동적 상태는 필요 시 `aria-live`로 알린다.
- 본문과 UI 텍스트는 WCAG AA 대비를 목표로 한다.

## 5. 테스트

- Vitest와 Testing Library를 사용한다.
- 핵심 사용자 흐름, 페이지네이션 경계, 로딩·오류·빈 상태, API 데모 전환을 우선 테스트한다.
- 구현 세부사항보다 사용자가 보는 텍스트와 역할 기반 쿼리를 선호한다.
- 변경 전 `npm test`와 `npm run build`를 통과시킨다.

## 6. 커밋

- 커밋 메시지는 Conventional Commits 형식(`type(scope): summary`)을 사용한다.
- `feat`, `fix`, `docs`, `test`, `refactor`, `chore` 중 목적에 맞는 타입을 선택한다.
- 한 커밋은 하나의 논리적 변경만 포함하고, 생성물(`dist`, coverage)과 비밀 값은 커밋하지 않는다.
- 커밋 전에 변경 파일과 테스트 결과를 확인한다.
- 모든 완료된 작업 단위는 관련 검증을 통과한 뒤 반드시 커밋하고 현재 원격 브랜치에 즉시 push한다. 원격 설정이나 권한 문제로 push할 수 없으면 작업을 완료로 보고하지 않고 원인을 명확히 공유한다.
